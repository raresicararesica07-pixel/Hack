RR CHEAT - HOST REQUIREMENTS
==========================

Everything the machine must have disabled, removed or configured before a
manual-mapped kernel driver will load and stay loaded. Plain checklist, in
execution order. Section 12 has the checks that confirm each layer.

Legend:  [ ] to do     [x] already satisfied on this machine (2026-11-14)


0. WHY THESE ITEMS EXIST
------------------------
Three independent Windows features can stop the map dead, and one can stop it
minutes later:

  HVCI / Memory Integrity   kernel pages become W^X enforced -> mapped image
                            has no executable pages -> DriverEntry never runs
  Vulnerable driver blocklist  refuses the loader driver used as the mapping
                            vector (Intel iqvw64e.sys family)
  Smart App Control         refuses any unsigned binary before it executes

PatchGuard (0x109 CRITICAL_STRUCTURE_CORRUPTION) is a separate layer: it does
not block the map, it kills the machine minutes later, on its own timer. No
setting below fixes it, because it is not a setting - it fires when something
edits a structure the kernel checksums. If you see 0x109 after a session, see
section 12 instead of re-running this checklist.


1. BIOS / UEFI   (enter with F2, Del or F10 at power-on)
--------------------------------------------------------
[ ] Secure Boot            -> Disabled
                             Security or Boot tab. With it enabled, test
                             signing cannot be armed and some loaders refuse
                             to start.

[x] TPM 2.0                -> may stay Enabled. Does not block mapping.
                             Only FACEIT AC requires it.

[x] VT-x / SVM             -> may stay Enabled. The hypervisor is disabled in
                             Windows, not in firmware.

[x] VT-d / IOMMU           -> may stay Enabled. Irrelevant to a software mapper.

Save and exit. A reboot is required for any change here.


2. WINDOWS SECURITY -> DEVICE SECURITY -> CORE ISOLATION
--------------------------------------------------------
Open: Start -> Windows Security -> Device security -> Core isolation -> Details

[ ] Memory integrity                              -> OFF   (HVCI; reboot needed)
[ ] Kernel-mode Hardware-enforced Stack Protection -> OFF
[ ] Credential Guard                              -> OFF
[ ] Local Security Authority protection           -> OFF
[ ] Secure Launch / System Guard                  -> OFF

Registry equivalent (admin PowerShell, reboot after):
  reg add "HKLM\SYSTEM\CurrentControlSet\Control\DeviceGuard" /v EnableVirtualizationBasedSecurity /t REG_DWORD /d 0 /f
  reg add "HKLM\SYSTEM\CurrentControlSet\Control\DeviceGuard\Scenarios\HypervisorEnforcedCodeIntegrity" /v Enabled /t REG_DWORD /d 0 /f
  reg add "HKLM\SYSTEM\CurrentControlSet\Control\LSA" /v LsaCfgFlags /t REG_DWORD /d 0 /f


3. HYPERVISOR FEATURES
----------------------
Control Panel -> Programs -> Turn Windows features on or off. Uncheck all:

[ ] Hyper-V                          (including every sub-feature)
[x] Virtual Machine Platform
[x] Windows Hypervisor Platform
[x] Windows Sandbox
[x] Windows Subsystem for Linux
[x] Microsoft Defender Application Guard
[x] Containers

Then, admin PowerShell:
  bcdedit /set hypervisorlaunchtype off
  bcdedit /set vsmlaunchtype Off

[ ] Docker Desktop, BlueStacks, LDPlayer, WSA, Android emulators
      -> uninstalled, not just closed. Each one starts the hypervisor.

[ ] VirtualBox / VMware
      -> not running during a session. Hypervisor access is exclusive.

Why: a live hypervisor re-enables HVCI enforcement even with the toggle off,
and the map fails with an access-denied style error that names nothing useful.


4. CODE INTEGRITY
-----------------
[ ] Vulnerable Driver Blocklist -> OFF
      reg add "HKLM\SYSTEM\CurrentControlSet\Control\CI\Config" /v VulnerableDriverBlocklistEnable /t REG_DWORD /d 0 /f

[ ] Smart App Control -> OFF
      Windows Security -> App & browser control -> Smart App Control -> Off
      One-way switch. Turning it back on requires a Windows reinstall.

[ ] Reputation-based protection -> OFF (all four toggles on that page)

[ ] App & browser control -> Exploit protection
      -> every override on this process set to Default, none Custom


5. WINDOWS DEFENDER
-------------------
Order matters: Tamper Protection first, or every later setting is silently
reverted.
You can disable it by yourself or use defendercontrol https://www.sordum.org/9480/defender-control-v2-1/ password:sordum

[ ] Tamper Protection        -> OFF
      Windows Security -> Virus & threat protection -> Manage settings
[ ] Real-time protection     -> OFF
[ ] Cloud-delivered protection -> OFF
[ ] Automatic sample submission -> OFF
[ ] Exclusion folder         -> C:\robrun

Admin PowerShell, after Tamper Protection is off:
  Add-MpPreference -ExclusionPath "C:\robrun"
  Set-MpPreference -DisableRealtimeMonitoring $true
  Set-MpPreference -PUAProtection 0
  Set-MpPreference -MAPSReporting 0
  Set-MpPreference -SubmitSamplesConsent 2

Scheduled scans:
  Task Scheduler -> Task Scheduler Library -> Microsoft -> Windows -> Windows Defender
  -> disable every task in that folder.

Why: `kd2.exe` is detected as HackTool:Win64/KDMapper. Real-time protection
quarantines it on execution, before it can map anything.


6. THIRD-PARTY ANTIVIRUS
------------------------
Uninstall, do not disable. Each one registers kernel callbacks and scans mapped
memory; a disabled UI leaves the driver loaded.

[ ] Bitdefender
[ ] Kaspersky
[ ] ESET
[ ] Avast / AVG
[ ] Norton / McAfee
[ ] Malwarebytes   (the free build ships a driver too)

Reboot after uninstalling. Check `fltmc` in an admin shell - its filter driver
must be gone before the next step matters.


7. ANTI-CHEAT   (what conflicts, what must be removed)
------------------------------------------------------
[ ] Riot Vanguard (Valorant) -> uninstall completely.
      vgk.sys loads at boot whether or not you launch the game, and blocks
      manual mapping outright. There is no "disable" state.
      Uninstall Valorant, then Vanguard, then reboot.

[ ] Easy Anti-Cheat -> set to manual start
      sc stop EasyAntiCheat_EOS
      sc config EasyAntiCheat_EOS start= demand
      Restore before playing: sc config EasyAntiCheat_EOS start= auto
                              sc start EasyAntiCheat_EOS

[ ] BattlEye -> same treatment
      sc stop BEService
      sc config BEService start= demand

[ ] FACEIT AC -> cannot coexist on the same Windows install.
      FACEIT requires Secure Boot ON, TPM 2.0 and HVCI ON - exactly items 1-3
      above in reverse. Installing it undoes this entire checklist.
      Options: a second Windows install on another partition or disk, or a
      second machine. There is no configuration that satisfies both.

[ ] Roblox Hyperion (Byfron) -> leave it alone.
      No toggle, no config, and none is needed. The driver reads target memory
      through kernel-translated copies and never opens a handle to the game,
      so handle-stripping protection has nothing to act on.


8. BOOT AND POWER
-----------------
[ ] Fast Startup -> OFF
      powercfg /h off
      This also removes hibernation. Without it, "Shut down" keeps the kernel
      session alive, so an already-mapped image survives what looks like a
      clean boot and the next map lands on a second device.

[ ] Sleep / Hibernate -> not used between map and play.
      On resume the old device object is still present, and the second map
      binds to a higher-numbered device name.

[ ] Windows Update -> pause for 7 days during a test window.
      Settings -> Windows Update -> Pause updates.
      An update can change PatchGuard and the driver blocklist overnight and
      invalidate a test you already passed.


9. OVERLAYS THAT FIGHT THE ESP
------------------------------
Each of these hooks presentation. With one active, the overlay flickers,
drops frames or fails to draw.

[ ] Xbox Game Bar            -> OFF   Settings -> Gaming -> Xbox Game Bar
[ ] Game Mode                -> OFF   Settings -> Gaming -> Game Mode
[ ] Discord overlay          -> OFF   User Settings -> Game Activity -> Overlay
[ ] NVIDIA App / GeForce Experience overlay -> OFF   Alt+Z -> Settings
[ ] AMD Adrenalin overlay    -> OFF
[ ] MSI Afterburner + RivaTuner (RTSS) -> closed. RTSS is the worst offender.
[ ] Nahimic / Sonic Studio / Armoury Crate -> stopped


10. PROJECT LOCATION
--------------------
[ ] Move the project out of any synced folder.

      robocopy "C:\Users\patri\OneDrive\Desktop\robrun" "C:\robrun" /E /MOVE

      OneDrive takes write locks on status.log and hotkeys.log exactly while
      the overlay is appending, and Files On-Demand can turn an .exe or .sys
      into a placeholder. Run from a local path only.

[ ] Confirm these four files exist in the run folder:
      kd2.exe
      kernel-mode.sys
      RobRunPort.exe
      WebView2Loader.dll


11. EXECUTION ORDER
-------------------
  1. BIOS: Secure Boot OFF                       -> save, exit
  2. Windows Features: hypervisor items off
  3. Core isolation: Memory integrity OFF
  4. Defender: Tamper OFF -> exclusions -> real-time OFF
  5. Anti-cheat: Vanguard uninstalled, EAC/BE on demand
  6. powercfg /h off
  7. Reboot                                      <- mandatory
  8. Unzip the package into a local path, e.g. C:\ROBRUN
  9. MAP-DRIVER.bat                              -> exit code 0
 10. Start the game, get into a match
 11. START.bat

Items 1-3 block the map. Items 4-11 make it survive a session.


12. VERIFICATION
----------------
Open an admin PowerShell and check by hand.

  msinfo32
    Virtualization-based security ....... Not enabled

  Get-CimInstance -Namespace root\Microsoft\Windows\DeviceGuard -ClassName Win32_DeviceGuard |
    Select-Object VirtualizationBasedSecurityStatus, SecurityServicesRunning
    Expect: 0 and an empty list.

  bcdedit /enum {current}
    Expect: hypervisorlaunchtype    Off

Crash history, no tools required:
  Event Viewer -> Windows Logs -> System -> Filter Current Log
    Event level  : Error
    Event IDs    : 1001
    Source       : Microsoft-Windows-WER-SystemErrorReporting
    Every row is one bugcheck. The message opens with the code and four
    parameters. 0x00000109 means PatchGuard; anything else is a different
    class of fault.

After a 4-5 hour session, that log must show no new 0x109 entry.

If 0x109 does return, bisect the mapper's trace cleanup instead of guessing.
Set one of these in the same shell before MAP-DRIVER.bat, and reboot between
attempts:

  set SMX_CLEANUP=all            reproduce
  set SMX_CLEANUP=pidb,mm,ci     without WdFilter
  set SMX_CLEANUP=pidb,mm,wd     without ci.dll

Default is pidb,mm.


13. DO NOT
----------
  - Do not disable DEP/NX (`bcdedit /set nx AlwaysOff`). It buys nothing here
    and weakens the kernel for no return.
  - Do not patch PatchGuard. It is not a setting; it is a hypervisor-grade
    project on its own and a separate failure mode.
  - Do not run MAP-DRIVER.bat twice in one boot "to be sure". The second call
    binds a new device and the first image stays resident either way.
  - Do not map a rebuilt driver over a live mapping. Reboot first.
  - Do not expect any of this to make the driver safe against FACEIT, Vanguard
    or HVCI. Those are not obstacles to route around; they are mutually
    exclusive designs.
